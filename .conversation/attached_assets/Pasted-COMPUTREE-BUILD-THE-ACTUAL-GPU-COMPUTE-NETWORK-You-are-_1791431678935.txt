COMPUTREE: BUILD THE ACTUAL GPU COMPUTE NETWORK

You are building Computree, a production-oriented GPU compute access platform.

Do not build this as a chatbot product.

Do not build this as a token landing page with fake compute claims.

Do not create mock GPU usage and present it as real.

Do not claim that NVIDIA directly receives COMPUTREE, ETH, WETH, or GLM.

The actual infrastructure model is:

COMPUTREE token
→ wallet eligibility
→ compute allocation
→ temporary Computree credential
→ Computree OpenAI-compatible API
→ Computree compute orchestrator
→ Golem requestor / Golem-Workers
→ GPU provider
→ NVIDIA GPU where available
→ Qwen/Ollama workload
→ response returned through Computree API

Computree is the infrastructure and access layer.

The first real workload must be Qwen running on a Golem GPU provider.

The first external application proof must be Open WebUI connected to Computree’s OpenAI-compatible API.

Use official Golem documentation as the source of truth:

==================================================

1. PRODUCT OBJECTIVE
    ==================================================

Computree allows eligible COMPUTREE token holders to access GPU compute through a temporary credential.

The user experience is:

1. Connect wallet.
2. Backend verifies COMPUTREE balance.
3. Backend calculates compute eligibility/allocation.
4. User generates a temporary Computree credential.
5. User can use the credential with supported applications.
6. OpenAI-compatible applications connect to:

https://api.computree.ai/v1

7. User submits a workload.
8. Computree authenticates the credential.
9. Computree checks allocation, limits, and rate limits.
10. Computree creates or routes the workload to available GPU infrastructure.
11. Golem is used as the first compute backend.
12. Qwen/Ollama runs on a Golem GPU provider.
13. The result is returned through the Computree API.
14. The dashboard records the job, compute usage, provider, worker, and cost.
15. Treasury records show crypto used to fund Golem compute.

The system must support multiple users and multiple simultaneous jobs.

Never implement one-device-one-order or one-user-one-job restrictions.

Every workload is isolated by job ID.
